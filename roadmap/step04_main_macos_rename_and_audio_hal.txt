Step 04 — main_macos rename, platform_stats inlining, audio HAL
Date: 2026-06-26
Goal: Tidy up the macOS host entry point's naming/file layout left over from
step 03, and add an I2S-based audio output HAL for the ESP32 target.

===========================================================================
WHAT WAS BUILT
===========================================================================

1. main/main_host.c -> main/main_macos.c
   - Renamed to match the "macos_hal" naming used elsewhere (the display
     backend is components/macos_hal/, not components/host_hal/).

2. Inlined platform_stats per platform, removed the standalone .c files
   - main/platform_stats_esp32.c and main/platform_stats_host.c were each a
     single pair of one-line-bodied functions (macjr_platform_flash_kb /
     macjr_platform_heap_free_kb) -- thin enough that a whole file per
     platform was more indirection than the code warranted.
   - Their bodies moved directly into main_esp32.c and main_macos.c
     (each entry point now defines its own flash/heap query next to
     app_main()/main()); main/platform_stats.h stays as the shared
     declaration both entry points implement and ide_screen.c calls
     through.
   - main/CMakeLists.txt and macos/CMakeLists.txt source lists updated to
     drop the removed files.

3. components/esp32s3_hal/audio/ — new ESP32-only HAL, adapted from a
   sample I2S sine-wave generator (audio.c/h): same I2S TX setup (16-bit
   mono, standard mode, BCLK=41/WS=42/DOUT=40), but the sine-wave self-test
   loop is gone and the API is now request/callback shaped instead of a
   blocking generate-forever loop:
     audio_init()    — brings up the I2S channel and a background
                        FreeRTOS task that owns it.
     audio_write(samples, sample_count, on_complete, ctx)
                     — non-blocking: queues the buffer (4-deep queue) and
                        returns immediately. The audio task performs the
                        actual i2s_channel_write() (looping until all
                        bytes are written) and then calls
                        on_complete(ctx, result) from the audio task, not
                        the caller's thread. `samples` is read in place,
                        not copied, so callers must keep it alive until
                        the callback fires.
     audio_deinit()  — posts a stop sentinel, waits for the task to exit,
                        tears down the channel.
   - components/esp32s3_hal/audio/CMakeLists.txt: REQUIRES esp_driver_i2s
     esp_driver_gpio freertos (esp_driver_gpio added explicitly since
     esp_driver_i2s only PRIV_REQUIRES it -- that doesn't propagate the
     driver/gpio.h include path to consumers).
   - Registered in root CMakeLists.txt's EXTRA_COMPONENT_DIRS, alongside
     display and sdcard. Not yet wired into main_esp32.c's app_main --
     there's no sample audio data to play yet.

===========================================================================
HOW IT WORKS
===========================================================================

  audio_write() producer (any task) -> request queue (depth 4) ->
  audio_task: dequeue -> i2s_channel_write() loop until done ->
  on_complete(ctx, result) -> back to dequeue
